# UX 設計

操作の流れ、操作ルール、文言、ミス防止の方針を定義する。画面部品は [ui-design.md](ui-design.md)。

## 1. 利用者像と最重要タスク

| 利用者 | 最重要タスク | 目標 |
|---|---|---|
| メンバー | 今日やることの把握、ステータス更新 | ログイン後 0 クリックで「期限切れ・今日」が見える。ステータス変更は 2 操作以内 |
| プロジェクト管理者 | タスク登録と割り振り、遅れの把握 | タスク登録はタイトル入力 + Enter のみでも可能。期限切れの一覧は 1 回の絞り込みで |
| 閲覧者 | 進捗確認 | 編集できない部品を出さず、読みやすい一覧 |
| システム管理者 | アカウント発行・停止 | 1 画面で完結 |

## 2. 主要フロー（詳細）

### F-1 タスクを素早く登録する（UF-02）

```text
タスク一覧で [N] キー または「＋ タスクを追加」
 → ダイアログ（タイトルにフォーカス）
 → タイトル入力 → [Enter] で登録（Shift+Enter は改行不可のため無効）
 → トースト「SALES-15 を追加しました [開く]」、一覧に追加（現在の絞り込みに合わない場合は「現在の絞り込み条件では表示されません」を付記）
 →（続けて追加 ON の場合）タイトル欄が空になり、そのまま次を入力
```
- 担当者・期限は「詳細を設定」から任意。既定値: 状態=既定ステータス、優先度=中、担当者=なし
- **理由**: 会議中の入力で項目の多さが入力の妨げになる（analysis/ui-ux.md R-UX-01）。

### F-2 朝の確認（UF-03）

```text
ログイン → ホーム（期限切れ・今日まで が上に展開）
 → 行のステータスをその場で変更（例: 未着手 → 対応中）
 → 詳細が必要ならタイトルをクリック → 詳細でコメント → ブラウザの戻る → ホーム（スクロール位置維持）
```

### F-3 担当の割り振り

```text
タスク一覧（表）→ 絞り込み「担当者: 未設定」
 → 各行の担当者セル → コンボボックスで名前を入力 → Enter
 → 担当者に「あなたが担当者になりました」のお知らせ
```

### F-4 遅れの把握（UF-04）

```text
プロジェクト → 絞り込み「期限: 期限切れ」→ 並び「期限が古い順」
 または ボード表示（期限切れカードは記号と色で目立つ）
 または マイルストーン一覧（期限切れ件数・進捗）
```

### F-5 初回ログイン（UF-01）

```text
SA から一時パスワードを受け取る → ログイン → パスワード変更画面（他画面に移動不可）
 → 変更完了 → ホーム（空状態: 「担当しているタスクはありません」）
```

### F-6 ステータスの削除（ミス防止の例）

```text
設定 → ステータス → 「確認待ち」の削除
 → ダイアログ「ステータス『確認待ち』を削除しますか？ このステータスのタスクが 4 件あります。移動先を選んでください。[移動先: 対応中 ▾]」
 → [削除して移動する]（赤）/ [キャンセル]（初期フォーカス）
```

### F-7 日程の確認と調整（Phase 9、UF-04）

```text
プロジェクト → 表示形式「ガント」（表示単位: 週）
 → まとめ方「担当者」で、人ごとの日程の重なりを見る
 → ⚠ の付いた棒（期限切れ）を右へドラッグ → 離すと保存（「保存しました」のトースト）
 →（キーボード）「表で見る」→ 期限の欄で日付を変更
 →「今日」で今日を含む期間に戻る
```
- 日程の変更は既存のタスク更新と同じ規則（権限・開始日 ≤ 期限・競合の扱い・変更履歴）
- **理由**: 遅れの把握から調整までを 1 画面で行える。マウスを使えない利用者のために、同じ操作を表の日付欄でもできるようにする

### F-8 割合の確認（Phase 9）

```text
プロジェクト → 表示形式「円グラフ」→ 割合を確認 → ステータス名を選ぶ → そのステータスで絞り込んだ表
ホーム → 「ステータス別の割合」→ 対象「すべてのプロジェクト（区分別）」または特定のプロジェクト
```

## 3. 操作ルール

| ルール | 内容 | 理由 |
|---|---|---|
| 自動保存と明示保存の使い分け | 選択式の属性（ステータス、担当者、優先度、期限、タグ、マイルストーン）は選んだ時点で保存。文章（タイトル、説明、コメント）は保存ボタン | 選択は取り消しやすく、文章は書きかけを保存されたくない |
| 削除は必ず確認 | タスク・コメント・添付・ステータス・タグ・マイルストーン・メンバー | 物理削除のため（[database-design.md](database-design.md) §1） |
| 確認ダイアログの文言 | 「何を」「どうなるか」を書く。ボタンは動詞（「削除する」）。「OK」「はい」は使わない | 誤操作防止 |
| 取り消し（元に戻す） | MVP では提供しない。代わりに確認と変更履歴で補う | 実装の複雑さに対して効果が限定的（OD-23） |
| 二重送信防止 | 送信中はボタン無効 + 「保存しています…」 | |
| 編集中の離脱 | タイトル・説明・コメントの未保存がある状態で離脱 → 「保存していない変更があります。破棄して移動しますか？」 | |
| 権限のない操作 | ボタンを表示しない。表示が必要な説明（設定画面）は 1 行で理由を書く | R-UX-08 |
| 競合 | 他の人が先に更新していたら最新を表示し、何が起きたかを伝える | 楽観的排他（[database-design.md](database-design.md) §6） |
| URL で再現 | 一覧の絞り込み・並び・表示形式・ページ、詳細の対象は URL で共有できる | 「この一覧を見てください」が URL で済む |
| URL で再現（Phase 9） | ガントの表示単位・期間の開始日・まとめ方・完了の表示、円グラフの対象（自分のタスク）も URL に保持する | 同上 |
| ドラッグには代替を必ず用意（Phase 9） | ガントの棒のドラッグと同じ変更を、表形式の代替表示の日付欄で行える | WCAG 2.2「2.5.7 ドラッグ動作」 |

## 4. キーボードショートカット

数を絞り、覚えやすいものだけにする（Plane の 2 ストローク方式は採用しない）。入力欄にフォーカスがある間は無効。`?` で一覧を表示。

| キー | 動作 | 有効な画面 |
|---|---|---|
| `/` | 検索欄にフォーカス | 全画面 |
| `N` | タスクを追加 | プロジェクト内、ホーム（プロジェクト選択から） |
| `G` → `H` | ホームへ | 全画面 |
| `Esc` | ダイアログ・メニューを閉じる | 全画面 |
| `?` | ショートカット一覧 | 全画面 |

すべてのショートカットは画面上のボタンでも同じ操作ができる（ショートカットは補助）。

## 5. 文言の方針（日本語）

| 方針 | 良い例 | 避ける例 |
|---|---|---|
| です・ます調、短く | タスクを追加しました。 | タスクの追加処理が正常に完了しました |
| 利用者の言葉 | 期限、担当者、ステータス | デッドライン、アサイニー |
| 主語と結果を書く | SALES-12 を削除しました。 | 削除成功 |
| エラーは原因 + 対処 | 期限は開始日以降の日付にしてください。 | 不正な値です |
| 責めない | 入力内容を確認してください。 | 入力が間違っています |
| ボタンは動詞 | 追加する / 保存 / 削除する / キャンセル | OK / 実行 |
| 数字と単位 | 3 件、10MB、2日超過 | — |
| カタカナ語は定着したものだけ | タグ、ステータス、マイルストーン、プロジェクト | イシュー、ワークアイテム、サイクル |

### 主要な文言

| 場面 | 文言 |
|---|---|
| タスク追加成功 | SALES-15 を追加しました |
| 削除確認（タスク） | タイトル: タスク SALES-12 を削除しますか？ / 本文: コメント・添付ファイル・変更履歴も削除され、元に戻せません。 / ボタン: 削除する |
| 削除確認（サブタスクあり） | このタスクにはサブタスクが 2 件あります。サブタスクもまとめて削除しますか？ / ボタン: サブタスクも削除する |
| アーカイブ確認 | タイトル: プロジェクト「営業支援」をアーカイブしますか？ / 本文: アーカイブすると、すべてのメンバーが閲覧のみできる状態になります。あとから元に戻せます。 |
| メンバー削除確認 | 山田 太郎さんをこのプロジェクトから外しますか？ 担当しているタスク 3 件は「担当者なし」になります。 |
| 利用停止確認 | 山田 太郎さんを利用停止にしますか？ すぐにログインできなくなります。担当中のタスクや履歴はそのまま残ります。 |
| 競合 | 他の人が先に更新しました。最新の内容を表示しています。 |
| 期限表示 | 今日 / 明日 / 10/9（木）/ 2日超過 / 期限なし |
| ガント（Phase 9） | 表示単位: 日 / 週 / 月、前へ / 今日 / 次へ、まとめ方: なし / 担当者 / ステータス / マイルストーン、完了・中止も表示、表で見る / ガントで見る、日付が未設定のタスク（◯件）、（開始日なし）（期限なし）、日程を変更しました、表示できるのは 500 件までです。期間を短くするか、表示単位を変えてください。 |
| 円グラフ（Phase 9） | ステータス別の割合、合計 ◯件、ステータス / 件数 / 割合、ステータス名を選ぶと、そのステータスのタスクを表で表示します。、すべてのプロジェクト（区分別） |
| 履歴 | 山田 太郎さんがステータスを「対応中」から「完了」に変更しました / 佐藤さんが期限を「10/9（木）」に設定しました / 担当者が外れました（メンバーから削除されたため） |
| お知らせ | 佐藤さんがあなたを SALES-12「見積書の作成」の担当者にしました / 佐藤さんが SALES-12「見積書の作成」にコメントしました / SALES-12「見積書の作成」が完了しました / 佐藤さんがあなたをプロジェクト「営業支援」に追加しました |

文言は `src/i18n/ja.ts` に集約し、画面のコード中に直接書かない。

## 6. 日付・時刻の表示

| 対象 | 表示 |
|---|---|
| 期限・開始日（今年） | `10/9（木）` |
| 期限・開始日（別の年） | `2027/1/15（金）` |
| 相対（期限） | 今日 / 明日 / 昨日 / ◯日超過 |
| 日時（コメント・履歴） | 1 時間以内「◯分前」、今日「14:05」、それ以前「10/3 14:05」、別の年「2025/10/3 14:05」。マウスオーバー（およびスクリーンリーダー用）で完全な日時 |
| タイムゾーン | 利用者の設定（既定 `Asia/Tokyo`）で表示 |

## 7. 性能体感

- 操作に対する反応は 100ms 以内に何かを表示（押下状態、楽観的更新）
- 1 秒以上かかる操作は進行状況を表示（アップロードは進捗バー）
- 一覧は前のデータを表示したまま次のデータを読み込む（ページ送りで画面が真っ白にならない）

## 8. レスポンシブの方針

| 幅 | 方針 |
|---|---|
| 〜767px | 1 列。一覧はカード、詳細は属性を先頭に。右下の追加ボタン。ボードは列を横スクロール（1 列ずつスナップ） |
| 768〜1023px | サイドナビ折りたたみ。表は列を減らす（マイルストーン列を非表示） |
| 1024px〜 | 全表示 |

スマートフォンでの最重要操作（自分のタスク確認・ステータス変更・コメント）を親指の届く範囲に置く。
