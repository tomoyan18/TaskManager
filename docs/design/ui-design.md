# UI 設計

画面・レイアウト・部品・Frontend の実装構成を定義する。操作の流れと文言の方針は [ux-design.md](ux-design.md)。Plane の画面・部品・文言は使わない（Phase 1 で抽出した「要求」だけを根拠にする）。

## 1. 設計の柱（優先順位は CLAUDE.md §14）

1. **分かりやすさ**: 1 画面 1 目的。用語を絞る（タスク・ステータス・担当者・期限・マイルストーン）
2. **操作しやすさ**: よく使う操作（追加・ステータス変更・担当者変更・期限変更）を一覧から 1〜2 操作で
3. **見つけやすさ**: ホームを「自分のタスク」に固定し、期限で区分
4. **読みやすさ**: 本文 15px・行間 1.6、日本語に合う字間、色だけに頼らない状態表示
5. **操作ミス防止**: 削除は確認必須、元に戻しにくい操作は文言で影響を説明、アーカイブを用意
6. **一貫性**: 同じ操作は同じ位置・同じ部品
7. **レスポンシブ**: 360px から利用可能
8. **見た目**: 落ち着いた配色・余白で情報を主役にする

## 3. デザイントークン

CSS 変数として `src/styles/tokens.css` に定義する。値は TaskManager 用に新規に決める。

### 3.1 色（ライトテーマのみ。ダークテーマは OD-21）

| トークン | 値 | 用途 |
|---|---|---|
| `--color-bg` | `#F7F8FA` | 画面背景 |
| `--color-surface` | `#FFFFFF` | カード・表・ダイアログ |
| `--color-border` | `#D9DDE3` | 区切り線 |
| `--color-text` | `#1F2933` | 本文（背景とのコントラスト 14:1 以上） |
| `--color-text-muted` | `#52606D` | 補足（4.5:1 以上） |
| `--color-primary` | `#1D5FBF` | 主ボタン・リンク・フォーカス（白文字で 4.5:1 以上） |
| `--color-danger` | `#B42318` | 削除・エラー |
| `--color-warning` | `#9A5B00` | 期限切れ表示（文字色として 4.5:1 以上） |
| `--color-success` | `#1E7A3D` | 成功 |
| `--focus-ring` | `0 0 0 3px rgba(29,95,191,.45)` | キーボードフォーカス |

ステータス・タグの 9 色パレット（`StatusColor`）は「淡い背景 + 濃い文字 + 左端の色帯」の組で定義し、すべての組で文字と背景のコントラスト 4.5:1 以上を確認して固定する（Phase 4 で値を確定し本書を更新）。利用者が自由な色コードを入力できないようにするのはこのため。

## 5. 画面設計

### SCR-01 ログイン

```text
        TaskManager
  ┌───────────────────────────┐
  │ ログイン                   │
  │ メールアドレス [____________] │
  │ パスワード     [__________][👁]│
  │ [        ログイン        ]   │
  │ パスワードを忘れた場合は、     │
  │ システム管理者に再発行を依頼してください。│
  └───────────────────────────┘
```
- 送信中はボタンを無効化し「ログインしています…」
- エラーはフォーム上部に `role="alert"` で表示（§8）

### SCR-02 パスワード変更（強制）
- 説明「最初に、ご自身で新しいパスワードを設定してください。」
- 項目: 現在のパスワード（一時パスワード）、新しいパスワード、新しいパスワード（確認）
- 新しいパスワードの下に規則と、入力に応じた充足状況（✓ 12 文字以上 など。色と記号の両方で表示）
- ナビゲーション・ヘッダー操作は非表示（ログアウトのみ可）

### SCR-04 ホーム（自分のタスク）

```text
自分のタスク                                   [□ 最近完了したものも表示]
┌ 期限切れ（2）──────────────────────────────────── 赤い左帯 ─┐
│ ⚠ 2日超過  SALES-12 見積書の作成   営業支援  [対応中 ▾] 至急 │
│ ⚠ 1日超過  SYS-3   パスワード規程の改訂 社内システム [未着手 ▾] 中 │
└──────────────────────────────────────────────────────┘
┌ 今日まで（1）┐ ┌ 今週（4）┐ ┌ それ以降（6）┐ ┌ 期限なし（3）┐（縦に並べる）
```
- 各行: 期限表示（「2日超過」「今日」「10/9（木）」）、タスクキー、タイトル（リンク）、プロジェクト名、ステータス（その場で変更できるメニュー）、優先度
- 区分ごとに折りたたみ可能。件数 0 の区分は見出しだけ表示し「ありません」
- **なぜ**: Phase 1 の要求 R-UX-04「自分の担当・期限切れにすぐ到達」。ホームに最も頻度の高い情報だけを置き、ダッシュボードのウィジェット（Plane のホーム）のような設定項目を持たない。

### SCR-05 プロジェクト一覧
- カードではなく **表**（名前、キー、自分のロール、未完了数、期限切れ数、管理者、更新日）。名前で並べ替え・絞り込み
- 右上「プロジェクトを作成」→ ダイアログ（名前、キー、説明）。キーは名前から英字を推測せず空欄で開始し、入力欄の下に「タスク番号の先頭に付きます（例: SALES-12）。後から変更できません。」
- 「アーカイブ済みも表示」切替
- **なぜ表**: プロジェクト数が数十になっても比較・検索しやすい

### SCR-06 タスク一覧（表）

```text
[表|ボード]  [＋ タスクを追加]                       [並び: 更新が新しい順 ▾]
絞り込み: [ステータス ▾][担当者 ▾][優先度 ▾][期限 ▾][タグ ▾][マイルストーン ▾] [🔍 タイトル]  条件をクリア
適用中: 担当者: 自分 ✕   期限: 期限切れ ✕
┌────┬──────────────────┬────────┬────┬──────┬────────┬──────────┐
│キー │タイトル              │ステータス  │優先度│担当者  │期限      │マイルストーン│
├────┼──────────────────┼────────┼────┼──────┼────────┼──────────┤
│SALES-12│見積書の作成 💬3 📎1 │[対応中▾] │至急 │[山田▾]│⚠ 10/4（土）│10月リリース│
│  └ SALES-13 見積の単価確認   │[未着手▾] │中   │[未設定]│10/8（水）│          │
└────┴──────────────────┴────────┴────┴──────┴────────┴──────────┘
                        1〜50 件 / 全 123 件   [< 前へ] 1 2 3 [次へ >]
```
- 既定: 未完了のみ・トップレベルとサブタスクを親の下に字下げ表示・更新の新しい順
- ステータス・担当者・優先度・期限のセルはクリック（または Enter）でその場で変更できる（ED 以上）
- 列見出しクリックで並べ替え（`aria-sort` を設定）
- 絞り込み・並び・表示形式・ページは **URL のクエリ** に保存（共有・戻る操作で再現）
- 行全体ではなくタイトルのリンクで詳細へ（セル内の操作と競合させない）
- **ページ送り（無限スクロールではない）**: 件数と位置が分かり、URL で共有できる（OD-22）

### SCR-07 タスク一覧（ボード）

```text
┌ 未着手 (5) ───┐┌ 対応中 (3) ───┐┌ 確認待ち (2) ─┐┌ 完了 (12) ─────┐
│┌───────────┐││┌───────────┐││              ││（既定では直近 14 日の│
││SALES-13      ││││SALES-12 至急 │││              ││ 完了のみ表示）      │
││見積の単価確認 ││││見積書の作成   │││              ││                    │
││山田 ・ 10/8   ││││山田 ・ ⚠10/4  │││              ││                    │
│└───────────┘││└───────────┘││              ││                    │
│ ＋ 追加         ││ ＋ 追加         ││ ＋ 追加        ││                    │
```
- 列 = ステータス（並び順）。完了区分の列は直近 14 日に完了したもののみ（API の `completedSince`）、中止区分の列は既定で非表示（「中止も表示」で表示）
- カード: キー、タイトル、担当者、期限（期限切れは記号 + 色 + 「超過」の文字）、優先度（至急・高のみ表示）
- ドラッグで列を移動 = ステータス変更。**キーボード / 支援技術向けにカードのメニュー「ステータスを変更」を必ず用意**
- 列内の並びは「優先度 → 期限 → 番号」で固定（手動並べ替えなし、OD-11）
- 各列下部「＋ 追加」で、そのステータスのタスクをタイトルだけで追加（インライン入力）
- 絞り込みは表と共通（URL も共通）

### SCR-20 タスク一覧（ガント）（Phase 9）

```text
[表|ボード|ガント|円グラフ]                                         [＋ タスクを追加]
表示単位 [日][週][月]  [‹ 前へ][今日][次へ ›]  2026/10/5〜2026/12/27   まとめ方 [なし ▾]  □ 完了・中止も表示  [表で見る]
┌ タスク ───────────────┬ 10/5   10/12   10/19 │今日 10/26 ... ──────────────┐
│ ▾ 山田 太郎（2）         │                      │                          │
│ SALES-12 見積書の作成     │   ▐対応中█████████▌ ⚠ 2日超過                     │
│ SALES-13 単価の確認       │            ▐未着手███▌                             │
│ ▾ 担当者なし（1）         │                      │       ◆ 10月リリース       │
│ SALES-14 上長承認（期限なし）│                   ▐▌                             │
└──────────────────────┴──────────────────────┴──────────────────────────┘
棒 = 開始日〜期限。色と文字 = ステータス。⚠ = 期限切れ。縦線 = 今日。◆ = マイルストーンの目標日
日付が未設定のタスク（4 件）: SALES-20 議事録の共有 / ...
```

- 左の列（タスクキー・タイトル）は横スクロールしても固定。時間軸は横スクロール（スマートフォンでも同じ）
- 表示単位と期間: 日 = 14 日（1 日 = 1 列）、週 = 12 週（月曜始まり、1 週 = 1 列）、月 = 12 か月（1 か月 = 1 列）。「前へ / 次へ」は日 7 日・週 4 週・月 3 か月ずつ、「今日」は今日を含む期間に戻す
- 棒: ステータスの色（淡い背景 + 濃い文字 + 色帯）と、ステータス名の文字。期限切れは警告色の太い枠 + ⚠ + 「◯日超過」。完了・中止は淡く表示し「完了」等の文字を付ける。開始日だけ・期限だけのタスクは 1 日の棒と「（期限なし）」「（開始日なし）」の文字
- 今日: 縦線 + 目盛りに「今日」の文字（期間外なら表示しない）
- まとめ方: なし / 担当者 / ステータス / マイルストーン。グループの見出しに件数。マイルストーンでまとめた場合、見出しの行に目標日の ◆ を表示
- 日程の変更（ED 以上、アーカイブ中は不可）: 棒をドラッグ = 開始日と期限を同じ日数ずらす、右端の取っ手をドラッグ = 期限を変える（開始日より前にはならない）。ドラッグ中は変更後の日付を棒の横に表示。離したら保存（失敗したら元に戻してトースト）
- キーボード・支援技術: 棒はタスク詳細へのリンク（Tab で移動できる）。日程の変更は「表で見る」の日付欄で行う
- 「表で見る」: 同じ行・同じまとめ方で表（キー、タイトル、ステータス、担当者、開始日、期限、日数、状態）。ED 以上は開始日・期限の入力欄
- 日付が未設定のタスク: 時間軸の下に別の枠（件数 + 先頭 50 件、タスク詳細へのリンク）
- 表示件数の上限（500 件）を超えた場合: 「表示できるのは 500 件までです。期間を短くするか、表示単位を変えてください。」
- 絞り込みバー（SCR-06）はガントでは表示しない（期間・まとめ方・完了の表示で操作する）
- **なぜ**: 期限と開始日の重なり・遅れを時間軸で見る要求（UF-04）。Plane のガント（サイドバー・ブロック・依存線）は参考にせず、TaskManager の既存部品（ステータスの色帯・期限切れの表示規則）で構成した

### SCR-21 タスク一覧（円グラフ）（Phase 9）

```text
[表|ボード|ガント|円グラフ]
ステータス別の割合                                    合計 12 件
   ┌───────┐   ┌ ステータス ─────┬ 件数 ┬ 割合 ─┐
   │ (円)  │   │ ▌未着手        │   5 │ 41.7% │
   │       │   │ ▌対応中        │   4 │ 33.3% │
   └───────┘   │ ▌確認待ち      │   0 │  0.0% │
               │ ▌完了          │   3 │ 25.0% │
               │ ▌中止          │   0 │  0.0% │
               └───────────────┴─────┴───────┘
ステータス名を選ぶと、そのステータスのタスクを表で表示します。
```

- 円: ステータスの色（`--sc-{color}-bar`）、扇形の間に白い区切り線。0 件のステータスは扇形を描かないが、表（凡例）には表示する
- 表（凡例を兼ねる）: 色見本 + ステータス名（リンク）、件数、割合（小数第 1 位、合計 100.0%）。並びはステータスの並び順
- 合計件数を見出しの横に表示
- スクリーンリーダー: 円は `role="img"` と要約（「ステータス別の割合。合計 12 件。未着手 5 件（41.7%）…」）。同じ内容は表でも読める
- 0 件: 円を描かず空状態「まだタスクがありません」（編集者以上には「タスクを追加」）
- 絞り込みバーは表示しない（プロジェクトの全タスクが対象）

### SCR-04 の追加（Phase 9）: ステータス別の割合

```text
自分のタスク                  [期限別|ステータス別の割合]
対象 [すべてのプロジェクト（区分別） ▾]               合計 9 件
 (円)  ┌ 区分 ──┬ 件数 ┬ 割合 ┐ ...
```
- 表示の切り替え「期限別」（既定）/「ステータス別の割合」（URL `?view=chart`）
- 対象: 「すべてのプロジェクト（区分別）」（既定）または参加中のプロジェクト（`&project=KEY`）。プロジェクトを選ぶとそのプロジェクトのステータスで表示し、ステータス名から「担当者: 自分」で絞り込んだ表へ移動できる
- 0 件: 「担当しているタスクはありません」

### SCR-08 タスク詳細

```text
営業支援 / SALES-12                                   [リンクをコピー][⋯]
┌ 本文（左 2/3）────────────────────────┐┌ 属性（右 1/3）──────────┐
│ 見積書の作成  ← クリックで編集              ││ ステータス  [対応中 ▾]       │
│ 説明（Markdown 表示）       [編集]          ││ 担当者      [山田 太郎 ▾]   │
│ ─────────────────────────── ││ 優先度      [至急 ▾]         │
│ サブタスク（1/2 完了）  [＋ サブタスクを追加] ││ 開始日      [10/1（水）]     │
│  ☑ SALES-13 見積の単価確認                   ││ 期限        [⚠ 10/4（土）2日超過]│
│  ☐ SALES-14 上長承認                         ││ マイルストーン [10月リリース ▾] │
│ ─────────────────────────── ││ タグ        [見積][急ぎ] ＋   │
│ 添付ファイル（1） [＋ ファイルを添付]          ││ 親タスク    なし              │
│ ─────────────────────────── ││ ─────────────            │
│ [コメント (3)] [変更履歴]  ← タブ            ││ 作成 佐藤 10/1 9:12          │
│  佐藤 10/2 10:00  単価表を共有します。        ││ 更新 山田 10/3 18:40         │
│  [コメントを入力…              ] [投稿]      ││                              │
└────────────────────────────┘└───────────────┘
```
- 属性は変更するとすぐ保存（自動保存。成功時は属性の横に小さく「保存しました」を 2 秒表示、トーストは出さない）
- タイトル・説明は「編集」→ 保存 / キャンセル（誤操作で長文を失わないよう明示保存）。編集中に離脱しようとしたら確認
- `⋯` メニュー: 「タスクを削除」（権限がある場合のみ）
- スマートフォンでは属性を本文の **上** にまとめて表示（ステータス・担当者・期限を先頭に）
- **なぜ専用ページ**: Plane は一覧上のサイドパネル（ピーク表示）が中心（analysis/ui-ux.md）。TaskManager は URL でそのまま共有でき、スマートフォンでも同じ構造で使える専用ページを基本にする。一覧からの文脈維持は「戻る」でフィルタ・ページ位置が URL から復元されることで担保する。

### SCR-09 タスク作成ダイアログ
- 必須はタイトルのみ。下に「詳細を設定」で開く任意項目（担当者、期限、優先度、ステータス、マイルストーン、タグ、説明、親タスク）
- 開いた画面の文脈を初期値に使う（ボードの列から開いたらそのステータス、マイルストーン詳細から開いたらそのマイルストーン、サブタスク追加なら親）
- 「続けて追加」チェック（オンなら登録後にタイトルだけ空にして入力を続ける）
- 登録成功: トースト「SALES-15 を追加しました」+「開く」リンク
- 未入力のまま閉じても確認なし。入力ありで閉じようとしたら「入力内容を破棄しますか？」

### SCR-10 / SCR-11 マイルストーン
- 一覧: 名前、目標日（期限切れ表示）、進捗バー（「8 / 12 件完了」の文字を併記）、期限切れ件数、状態
- 詳細: 説明、進捗、所属タスクの表（SCR-06 と同じ部品、マイルストーンで絞り込み済み）

### SCR-12〜14 プロジェクト設定
- 左に設定メニュー（基本情報 / メンバー / ステータスとタグ）、右に内容
- 閲覧者・編集者には読み取り専用で表示（なぜ編集できないかを上部に 1 行で表示「設定の変更はプロジェクトの管理者のみ行えます。」）
- 基本情報: 名前・説明・キー（変更不可の表示）、「アーカイブ」領域（危険操作として下部に区切って配置）
- メンバー: 表（名前、メール、ロール選択、参加日、削除）、「メンバーを追加」→ 利用者検索コンボボックス + ロール選択
- ステータス: 並べ替え可能なリスト（ドラッグ + 「上へ」「下へ」ボタン）、名前・区分・色・既定。削除時に移動先を選ぶダイアログ
- タグ: 名前・色・使用数

### SCR-15 お知らせ
- 「未読のみ」切替、「すべて既読にする」
- 1 行: 未読マーク（●と「未読」の視覚的に隠したテキスト）、本文、相対時刻（「5 分前」、1 日以上は日付）
- 行をクリックで既読にしてリンク先へ
- ヘッダーのベルからは最新 10 件のパネル（ポップオーバー）+「すべて見る」

### SCR-16 個人設定
- プロフィール（表示名、タイムゾーン）、パスワード変更

### SCR-17 利用者管理
- 表（表示名、メール、ロール、状態バッジ: 利用中 / 停止中 / ロック中 / パスワード未変更、最終ログイン）
- 「利用者を追加」→ 登録後に **一時パスワード表示ダイアログ**（コピー用ボタン、「この画面を閉じると、一時パスワードは再表示できません。」、閉じる前に確認チェック「利用者に伝えました」）
- 行メニュー: 編集、ロック解除、パスワードを再発行、利用停止 / 再開

### SCR-18 / SCR-19
- 404: 「ページが見つかりません。URL が間違っているか、閲覧する権限がない可能性があります。」+ ホームへ
- エラー: 「問題が発生しました。」+ 再読み込みボタン + 問い合わせ用の識別子（traceId）

### 7.1 ルーティング（React Router）

- ページ単位でコード分割（`lazy`）
- 画面タイトル（`document.title`）: 「見積書の作成（SALES-12）｜営業支援｜TaskManager」の形式

### 7.2 状態の持ち方

| 状態 | 置き場所 |
|---|---|
| サーバーのデータ | TanStack Query のキャッシュ。キー例 `["projects", key]`, `["tasks", key, filters]`, `["task", key, number]`, `["notices","unreadCount"]` |
| 絞り込み・並び・表示形式・ページ | URL クエリ（`useSearchParams` をラップした `useTaskListParams`） |
| 認証（アクセストークン・現在の利用者） | `AuthProvider`（React context、メモリのみ） |
| トースト | `ToastProvider` |
| サイドナビの折りたたみ | localStorage（失敗時は既定値） |

### 7.3 データ取得・更新の方針

- 一覧の `staleTime` 30 秒、詳細 10 秒。画面復帰時に再取得
- 属性の変更（ステータス・担当者・優先度・期限）は **楽観的更新**: 先に画面を更新し、失敗時は元に戻して失敗トースト。409（競合）の場合は最新を再取得し「他の人が先に更新しました。最新の内容を表示しています。」
- 作成・削除は応答を待ってから反映（番号が確定するため）
- お知らせ未読件数: 60 秒間隔 + ウィンドウのフォーカス時

### 7.4 API クライアント

- `src/api/client.ts`: openapi-fetch のクライアント。ミドルウェアで `Authorization` 付与、401 時のリフレッシュと再送、Problem Details を `ApiError`（`status`, `code`, `title`, `detail`, `fieldErrors`, `traceId`）に変換
- `src/api/schema.d.ts`: `openapi-typescript docs/api/openapi.v1.json` の生成物（手で編集しない）
- 機能ごとのフック: `useTaskList`, `useTask`, `useCreateTask`, `useUpdateTask`, `useDeleteTask`, `useMyTasks`, `useUnreadNoticeCount` など

### 7.5 型

- API の型は生成物から別名定義のみ（`type TaskSummary = components["schemas"]["TaskSummaryResponse"]`）
- 画面専用の型（絞り込み条件など）は各 feature の `types.ts`

### 7.6 フォームと検証

- react-hook-form + zod。制約値（文字数など）は `src/constants/limits.ts` に API 設計と同じ値で定義
- 送信時にクライアント検証 → API の 400 `errors` を各項目にマッピング（`setError`）。項目に対応しないエラーはフォーム上部
- エラー表示: 項目の下に赤文字 + アイコン、`aria-describedby` で関連付け、送信時は最初のエラー項目にフォーカス

### 7.7 エラー処理

| 状況 | 振る舞い |
|---|---|
| 400 | フォームの項目エラー |
| 401 | リフレッシュ → 失敗ならログインへ |
| 403 `auth.password_change_required` | SCR-02 へ |
| 403 `access.forbidden` | トースト |
| 404（ページの主データ） | SCR-18 |
| 409 | `title` + `detail` をトースト（競合は再取得） |
| 413 / 415 | 添付欄に表示 |
| 429 | トースト「しばらく時間をおいてから再度お試しください。」 |
| 500 / ネットワーク | トースト（操作）または ErrorPanel（表示）。traceId を「詳細」に表示 |
| 描画時の例外 | ルート単位のエラー境界 → SCR-19 |

## 8. アクセシビリティ（WCAG 2.2 AA）

- 全操作をキーボードで可能に（ボードのステータス変更はメニューで代替）
- フォーカスは常に見える（`--focus-ring`）。ダイアログはフォーカスを閉じ込め、閉じたら開いた要素に戻す（React Aria の機能）
- 色だけで情報を伝えない（期限切れ = 記号 + 文字 + 色、優先度 = 記号 + 文字）
- コントラスト 4.5:1（本文）/ 3:1（大きな文字・UI 部品の境界）
- 画面遷移時に見出しへフォーカスを移し、`document.title` を更新
- 動きを減らす設定（`prefers-reduced-motion`）でアニメーションを止める
- 画像・アイコンだけのボタンには `aria-label`（「お知らせ（未読 3 件）」）
- フォームのラベルは常に表示（プレースホルダをラベルの代わりにしない）
- 自動検査（axe）を E2E テストに組み込む
