# UI/UX 解析（Plane `preview`）

## 目的

Plane の UI を見た目ではなく「情報構造・操作頻度・画面遷移・操作ミス防止」の観点で解析し、TaskManager の新しい UI/UX 設計（Phase 2）に使える **要求** を抽出する。Plane のデザイン・コンポーネント・文言はコピーしない（CLAUDE.md §14）。

## 解析範囲と根拠

- 画面ルート: `apps/web/app/routes/core.ts`
- 一覧: `components/issues/issue-layouts/**`（list / kanban / calendar / gantt / spreadsheet、filters、quick-add、quick-action-dropdowns、empty-states）
- 詳細: `components/issues/issue-detail/*`、`components/issues/peek-overview`
- モーダル: `components/issues/issue-modal/*`、`delete-issue-modal.tsx`、`archive-issue-modal.tsx`
- 一括選択: `store/multiple_select.store.ts`、`components/issues/bulk-operations/root.tsx`
- ショートカット: `components/power-k/config/*`
- 文言: `packages/i18n/src/locales/ja/*.json`
- 実画面は起動していない（Phase 1 ではコードからの解析のみ）

## Navigation / 情報階層（確認済み）

```text
ワークスペース
├─ ホーム（ウィジェット: 最近見た項目、クイックリンク、付箋）
├─ 自分の作業 / 受信箱（通知） / 下書き / 付箋 / 分析 / ワークスペースビュー / アクティブなサイクル
├─ プロジェクト一覧
│    └─ プロジェクト
│         ├─ 作業項目（既定タブ）
│         ├─ サイクル / モジュール / ビュー / ページ / 受付（プロジェクト設定で ON/OFF）
│         └─ アーカイブ
└─ 設定（ワークスペース / プロジェクト / 個人）
```

- サイドバーにプロジェクトを並べ、展開してプロジェクト内機能に移動（表示件数の上限 `navigation_project_limit` 既定 10、アコーディオン / タブ切替の設定あり）。
- お気に入り（フォルダ可）をサイドバー上部に固定。
- パンくずリストで階層を表示。
- 識別子 URL（`/:ws/browse/ABC-12`）で作業項目に直接アクセス可能。

## 操作頻度の高い操作（コードから推定、有力）

| 操作 | 実現手段（Plane） | 根拠 |
|---|---|---|
| 作業項目の作成 | どこからでもショートカット（`c` / `ni`）、一覧のクイック追加（グループ毎のインライン入力）、作成モーダル | `quick-add/`、power-k |
| 状態・担当者・優先度・ラベル・期限の変更 | 一覧の各行のプロパティを直接ドロップダウンで変更（詳細を開かない）、単一キー（s / a / p / l） | `issue-layouts/properties/`、power-k |
| 詳細の確認 | 一覧上のサイドパネル（ピーク表示）で開き、一覧の文脈を保つ | `peek-overview` |
| 並び替え・状態変更 | カンバンのドラッグ&ドロップ | pragmatic-drag-and-drop |
| 絞り込み | フィルタ行 + 保存ビュー | `work-item-filters/` |
| 通知の確認 | 受信箱（未読 / メンション / アーカイブ / スヌーズ） | 通知 API の Query |

## 画面遷移

```text
サインイン → (未オンボーディング) オンボーディング → (ワークスペースなし) 作成 → ホーム
ホーム → プロジェクト → 作業項目一覧 ⇄ ピーク表示 → (必要時) 全画面詳細
通知 → 該当作業項目
```

- サインイン後の遷移先はサーバー側で決定（`get_redirection_path`）。`next_path` で元の画面へ戻る。

## Form complexity

- 作成モーダル: タイトル（必須）、説明（リッチテキスト）、プロジェクト選択、状態、優先度、担当者、ラベル、開始日、期限、見積もり、サイクル、モジュール、親。既定値（既定状態・既定担当者）で入力を省略可能。
- 「続けて作成」オプション、下書き保存（モーダルを閉じる際に下書きとして残す）（有力）。
- タイトル必須・最大長の検証をクライアントで実施。

## Table / List behavior

- 5 レイアウト（リスト、カンバン、カレンダー、ガント、スプレッドシート）をユーザーが切替。選択はユーザー × プロジェクト単位でサーバー保存。
- グループ化（状態 / 優先度 / 担当者 / ラベル / サイクル / モジュール 等）とサブグループ化、空グループの表示切替、表示列の選択。
- 無限スクロール（グループ毎の追加読み込み）、仮想化（大量データ対応）。

## Search / Filter / Sorting

- ワークスペース全体検索（プロジェクト、作業項目、サイクル、モジュール、ページ、ビュー）。コマンドパレットから利用。
- フィルタ: 状態 / 状態グループ / 優先度 / 担当者 / メンション / 作成者 / ラベル / 開始日 / 期限 / サイクル / モジュール / 購読中 等。日付は相対指定（今週、期限切れ等）に対応。
- 並び替え: 手動（ドラッグ）、作成日、更新日、開始日、期限、優先度、番号など。

## Bulk operation

- 複数選択ストアはあるが、CE の一括操作バーは有償版の案内のみ（確認済み）。CE で使える一括操作は一括削除・一括アーカイブ・一括日付変更 API。

## Modal / Dialog / 操作ミス防止

- 削除確認モーダル（対象種別を文言に含める、成功・失敗をトースト表示、権限エラーを専用文言で表示）。
- アーカイブ（削除より軽い「片付け」）と、論理削除の復元（ファイル）を用意。
- 自動アーカイブ / 自動クローズで放置項目を整理。
- 権限のない操作はボタン自体を非表示（`allowPermissions`）。

## Notification / Loading / Empty / Error state

- トースト（成功 / 失敗 / 警告）。
- 更新中インジケータ（画面右上の小さなスピナー）、初回読み込みはローダー。
- 空状態コンポーネントが多数（`ja/empty-state.json` 270 行）: 「まだ何もない」理由と次の行動（作成ボタン）を提示。フィルタ結果 0 件とデータ 0 件を区別（有力）。
- エラー境界・404 ページ。

## Responsive behavior

- Tailwind のブレークポイント指定を含むコンポーネントは 121 ファイル。モバイル専用オンボーディング設定（`is_mobile_onboarded`）があり、モバイルアプリが別に存在することが示唆される（有力）。Web のモバイル最適化の度合いは実画面を見ていないため不明（Q-UX-01）。

## Keyboard operation

- コマンドパレット（Cmd/Ctrl + K 相当、`cmdk`）と 2 ストローク・ショートカット（g/n/o + キー）。詳細は [frontend.md](frontend.md)。
- 一覧上の単一キーでのプロパティ変更。

## Accessibility

- `aria-*` 属性 299 箇所、`role=` 41 箇所（`components/` 内）。`accessibility.json` に aria ラベル文言を用意。
- Base UI（ヘッドレス）を利用しフォーカス管理を部品側に委ねている（有力）。
- 色だけで状態を区別していないか、コントラスト比は未検証（Q-UX-02）。

## 日本語表示

- `ja` ロケールあり。ただし文言は Plane 固有の用語・翻訳であり、TaskManager に流用しない（CLAUDE.md §10・§15）。

## TaskManager の UI/UX 設計に使える要求（抽出）

| # | 要求 | 優先順位の観点（CLAUDE.md §14） |
|---|---|---|
| R-UX-01 | 作業項目を最小入力（タイトルのみ）で素早く作成できる。既定値で残りを補う | 操作しやすさ |
| R-UX-02 | 一覧から詳細を開かずに状態・担当者・期限・優先度を変更できる | 操作しやすさ |
| R-UX-03 | 一覧の文脈を保ったまま詳細を確認できる（サイドパネル等） | 情報を見つけやすい |
| R-UX-04 | 「自分の担当」「期限切れ」「今週期限」などの横断ビューにすぐ到達できる | 情報を見つけやすい |
| R-UX-05 | フィルタ・グループ化・並び順をユーザー毎に保持する | 一貫性 |
| R-UX-06 | 人が読める作業項目番号（例: プロジェクト略称 + 連番）で検索・URL アクセスできる | 分かりやすさ |
| R-UX-07 | 削除は確認ダイアログを必須とし、削除より軽い「アーカイブ」を用意する | 操作ミス防止 |
| R-UX-08 | 権限のない操作は表示しない、または無効化して理由を示す | 分かりやすさ / 操作ミス防止 |
| R-UX-09 | 空状態では理由と次の行動を示す。フィルタ結果 0 件とデータ 0 件を区別する | 分かりやすさ |
| R-UX-10 | 成功・失敗をトーストで即時に知らせ、失敗時は何をすればよいかを示す | 分かりやすさ |
| R-UX-11 | 主要操作にキーボードショートカットを用意する（ただし数は絞る） | 操作しやすさ |
| R-UX-12 | 通知は未読・メンションで絞り込め、通知から該当項目へ 1 クリックで移動できる | 情報を見つけやすい |
| R-UX-13 | スマートフォン幅でも一覧・詳細・作成が使える | レスポンシブ |
| R-UX-14 | 状態は色だけでなくアイコン・文字でも区別する | 読みやすさ / アクセシビリティ |

## Plane の UI で避けたい点（設計候補）

- 機能・レイアウト・設定項目が多く、初見の利用者には情報量が多い（画面ルート 70 以上、プロジェクト設定 10 画面以上）。
- サイクル / モジュール / ビュー / ページ / 受付と、似た「束ねる」概念が並ぶ。

## 不明点

- 実画面のレスポンシブ挙動（Q-UX-01）
- 色コントラスト・スクリーンリーダー対応の実態（Q-UX-02）

## Phase 2 で決定する事項

- 画面一覧と画面遷移図
- ナビゲーション構造（サイドバーの項目）
- 一覧のレイアウト種類（リスト / カンバン / カレンダー）
- 作業項目詳細の表示方式（全画面 / サイドパネル / モーダル）
- ショートカットの範囲
- 日本語の用語集（作業項目、担当者、期限、状態名など）
- デザイントークン（色・余白・タイポグラフィ）と UI 部品の方針
