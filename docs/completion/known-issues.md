# 既知の課題（Phase 8 時点）

- 作成日: 2026-10-13
- 未解決の **Critical / High はなし**。機能の動作を妨げる未解決の不具合もなし。
- 以下は、利用者の対応が必要な事項、受け入れたリスク、今後の改善候補である。出典の詳細は各リンク先。

## 1. 利用者の対応が必要な事項

| ID | 内容 | 重大度 | 対応 |
|---|---|---|---|
| KI-01 | ルートの `CLAUDE.md`（§11）と `.claude/skills/phase-05-test-code/CLAUDE.md` に、ローカル PC の MySQL の利用者名とパスワードが平文で書かれている。どちらも Git 未追跡（[security-review.md](../security/security-review.md) SEC-04） | Medium | **コミットする前に**パスワードを削除する（環境変数などで渡す）。コミットしてしまった場合はパスワードを変更する。アプリのコード・設定・イメージ・ドキュメントには含まれていないことを確認済み |
| KI-02 | DB の root を「コンテナ内からのみ」に制限する設定（`MYSQL_ROOT_HOST=localhost`）は、新しく作る DB にしか反映されない（SEC-03） | Low | Phase 7 より前に作った DB ボリュームを使い続ける場合は `DROP USER 'root'@'%';` を実行する（README §12） |

## 2. 受け入れたリスク（設計上の判断）

| ID | 内容 | 判断の理由 |
|---|---|---|
| KI-03 | ログアウト後も、発行済みのアクセストークンは最長 15 分有効（SEC-10） | トークンはメモリのみに保持し、パスワード変更・利用停止は即時に失効する。社内利用の前提 |
| KI-04 | 5 回失敗してロックされたときの応答で、そのメールアドレスの利用者が存在することがわかる（SEC-10） | 案内の分かりやすさを優先。ログインは IP あたり 10 回/分に制限 |
| KI-05 | 既知の利用者を 5 回の失敗でロックできる（嫌がらせ）（SEC-10） | 15 分で自動解除、システム管理者が解除可能 |
| KI-06 | プロジェクトの管理者は全利用者を名前・メールで検索できる。誰でもプロジェクトを作れるため実質的に社内名簿になる（SEC-10） | 社内ツールの名簿として受け入れ。検索は最大 20 件、停止中の利用者は出さない |
| KI-07 | DB 接続は TLS 必須だが、サーバー証明書を検証していない（SEC-INFO-01） | 内部ネットワークのみ。外部の DB を使う場合は `SslMode=VerifyCA` を設定する |

## 3. 運用上の注意

| ID | 内容 | 対応 |
|---|---|---|
| KI-08 | web コンテナは HTTP（8080）のみ。HTTPS・HSTS は前段のリバースプロキシ・ロードバランサーで設定する前提（SEC-INFO-02） | README §12 に記載 |
| KI-09 | 画面の CSP（nginx）に、react-aria が挿入する固定のスタイルのハッシュを指定している | react-aria を更新して画面のスタイルが変わった場合は、ブラウザの CSP 違反のメッセージに出るハッシュに置き換える（`docker/web/nginx.conf` のコメント）。E2E-08 が違反を検出する |
| KI-10 | API コンテナのログに ASP.NET Core DataProtection の Warning が 3 件出る（鍵をメモリに置く件） | 本アプリは DataProtection を使っていない（リフレッシュ Cookie は乱数のトークン）。動作に影響しない |
| KI-11 | Swagger を無効にした本番構成で `/swagger` は 404 ではなく 401（SEC-INFO-05） | 公開はされない |
| KI-12 | ベースイメージはタグで固定しているが、ダイジェストでは固定していない（SEC-INFO-04） | 公式イメージの更新時は DB の派生イメージも作り直し、Trivy などで再確認する |
| KI-13 | Docker Desktop が無応答になることがあった（docs/environment/issues.md I-01） | Docker Desktop を再起動する。アプリの不具合ではない |
| KI-14 | E2E は前のシナリオの結果を使うため、空の DB（`docker compose down -v` の直後）から通しで実行する必要がある | docs/testing/test-design.md §8 |
| KI-15 | 日付の入力欄はブラウザ標準の部品のため、表示形式（`mm/dd/yyyy` など）はブラウザの言語設定に従う | 日本語のブラウザでは `yyyy/mm/dd` になる。値の保存・表示（`10/16（金）` など）は日本語の形式 |

## 5. Phase 9（ガントチャート・ステータス別円グラフ）で追加した事項（2026-10-16）

| ID | 内容 | 対応 |
|---|---|---|
| KI-20 | 割合は最大剰余法で合計 100.0% にそろえるため、件数が同じ項目でも 0.1% の差が出ることがある（例: 1 件ずつの 3 項目は 33.4% / 33.3% / 33.3%。端数が同じなら並び順で先の項目に配る） | 仕様（docs/design/domain-model.md §5.2 SR-02、OD-36）。件数も必ず表示している |
